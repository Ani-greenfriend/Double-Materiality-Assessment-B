## Section 1 — Tool Summary

**Tool name:** Apus DMA — Expert Survey

**What it does:** A web page opened through a personal invitation link, where one invited expert rates the ESRS double-materiality topics (Impacts, Risks, Opportunities — "IROs") of one assessment. It shows one topic per page with every applicable criterion, collects a justification for each rating, saves progress so the expert can leave and resume, and submits the complete response as one record.

**Who uses it:** Invited experts and stakeholder representatives of a client company — for example employees, suppliers, customers, investors, lenders, NGOs, subject-matter experts — and representatives of **silent stakeholders** (parties that cannot speak for themselves, such as nature, represented by a proxy such as an ecologist or nature NGO). No account is needed; the personal link is the only access.

**Why it exists:** Lets a sustainability consultant collect individually rated, justified expert input for an ESRS double materiality assessment at the granularity (Scale / Scope / Irremediability / Likelihood, or Magnitude / Likelihood) that makes the result audit-defensible, while proving who was invited and who responded, without any expert creating an account.

**Build status:** Iteration — the previous version (v1.1, "Participant Questionnaire") was an anonymous questionnaire opened through one shared link per assessment, with per-criterion ratings, an optional overall comment, no justification, no stakeholder-expertise capture and no save-and-resume. This build renames the tool, replaces the shared link with personal invitation links, adds the About you screen, per-rating justifications, save and resume, and the submission record, and changes the GDPR outcome from "not applicable" to "applies". Only the demo assessment (`acme-2026`) exists; there is no real response data to migrate.

## Section 5 — Data Architecture

### Terminology (applies to both specs)

- **Expert survey** — an assessment type where invited experts answer through Tool A. Database value: `expert_survey`.
- **Expert live session** — an assessment type run by the consultant in Tool B with a group. Database value: `expert_live_session`.
- **Cycle** — one DMA round for one client (for example a financial year). It groups the expert survey and the expert live session that are combined into one result.
- **Assessment** — one expert survey or one expert live session inside a cycle.
- **Invitation** — one invited expert of an expert survey, with a personal link.
- **Submission** — one expert's whole response (survey) or one live session's whole result.

### What data is collected or stored by this tool

| Field name | Plain language label | Data type | Who provides it | Required? |
|-----------|---------------------|-----------|----------------|-----------|
| assessment_id | Which assessment this response belongs to | UUID (FK) | From the invitation | Yes |
| invitation_id | Which invitation this response belongs to | UUID (FK) | From the personal link | Yes |
| source | Where the response came from | Text — `expert_survey` | Automatic | Yes |
| status | Whether the response is still a draft | Text — `draft` or `submitted` | Automatic | Yes |
| stakeholder_group | The group the expert answers as (including silent stakeholder groups) | Text | Expert (About you) | Yes |
| perspective | Impact or financial | Text — `impact` or `financial` | Derived from the chosen group | Yes |
| expertise_topics | Fields of expertise | List of E1, E2, E3, E4, E5, S1, S2, S3, S4, G1, Other / cross-cutting (multi-select, at least one) | Expert | Yes |
| expertise_explanation | Written explanation of the expertise | Text | Expert | Yes |
| title | Job title or role (kept general) | Text | Expert | No |
| basis_for_representation | For silent stakeholder representatives: the study, method or mandate they rely on | Text | Expert (only shown when a silent stakeholder group is chosen) | No |
| overall_comment | "Any other comments?" | Text | Expert | No |
| consent_given_at | When the expert accepted the data statement | Timestamp | Automatic | Yes |
| current_topic_index | Where to resume | Integer | Automatic | Yes |
| last_saved_at | When progress was last saved | Timestamp | Automatic | Yes |
| submitted_at | When the response was submitted | Timestamp | Automatic | Only once submitted |
| iro_id | Which IRO a rating rates | UUID (FK) | From the assessment's topic list | Yes |
| criterion_key | Which criterion a rating rates | Text — `scale`, `scope`, `irreversibility`, `likelihood`, `magnitude` (for a risk or opportunity the `likelihood` row is the financial likelihood; there is no separate `financialLikelihood` key) | Fixed by the IRO's type | Yes |
| value | The 0–5 rating, or empty if skipped | Integer 0–5, nullable | Expert | No — a skip leaves it empty on purpose |
| justification | Why the expert gave this rating | Text | Expert | Required whenever a rating has a value and the assessment's justification mode is per criterion |
| topic justification | One justification per topic (used when the assessment's justification mode is per topic) | Text | Expert | Required when any criterion on the topic has a value and the mode is per topic |

**Tables owned and written by this tool:**

| Table name | What it stores | Key fields |
|-----------|---------------|-----------|
| submissions | One row per expert response (draft or submitted) | id, assessment_id, invitation_id, source, status, stakeholder_group, perspective, expertise_topics, expertise_explanation, title, basis_for_representation, overall_comment, consent_given_at, current_topic_index, last_saved_at, submitted_at |

| topic_justifications | One row per (IRO) per submission when the assessment's justification mode is per topic | id, submission_id, iro_id, justification |

## Section 6 — Access and Permissions

Not applicable — no authentication on this tool (A1).

**Access is by personal link code.** The personal link is the survey address plus the assessment slug and the invitation's unguessable link code: `/survey/[assessment slug]/[link code]`. The link code is a secret that a caller must already hold — it can never be listed or looked up from the database.

**The public side never touches the sensitive tables directly.** Anon has **no table-level access at all** to `invitations`, `submissions`, `ratings` and `topic_justifications`. All public reads and writes go through six `SECURITY DEFINER` functions, each keyed by the link code and touching only that invitation's data. None returns `name` or `email`, and none deletes:

| Function | What it does |
|----------|--------------|
| lookup_invitation(link code) | Returns the invitation's id, assessment, status and submitted time (zero or one row) |
| mark_invitation_opened(link code) | Moves the invitation from invited to opened |
| get_draft(link code) | Returns the expert's own draft submission, ratings and topic justifications, or nothing |
| create_draft(link code, About you fields) | Creates the one draft for that invitation (sets the assessment and consent time server-side) |
| save_progress(link code, topic index, ratings, topic justifications) | Saves draft progress; refuses once submitted |
| submit_survey_response(link code, overall comment, ratings, topic justifications) | The all-or-nothing submit: writes every rating and justification and marks the submission and invitation submitted; rejects a second submit |

**RLS — who can read and write what:**

| Table | User type | Can read | Can insert | Can update | Can delete |
|-------|-----------|----------|------------|------------|------------|
| assessments, iros, clients, stakeholder_groups | Unauthenticated (anon) | All rows (display content only; row scoping is not possible without an auth identity) | No | No | No |
| cycles | Unauthenticated (anon) | Only the columns id, esrs_version, stage and client_id (column grant) — thresholds and sign-off fields stay internal | No | No | No |
| invitations, submissions, ratings, topic_justifications | Unauthenticated (anon) | **No direct access** — only through the six functions above | No direct access | No direct access | No |
| stakeholder_members and every other table | Unauthenticated (anon) | No | No | No | No |

> A submitted response cannot be changed or deleted from the public side. Opening a personal link whose submission is already submitted shows an "already submitted" screen only. Claude Code builds all policies and functions via Supabase MCP; RLS is never disabled on any table.
>
> **Known limitation (single-client testing):** the public key can read the display tables in full — every assessment's name, welcome text and topic list, client names and logos, and the stakeholder group names. This is acceptable with one client. Before a second client is onboarded, route these reads through link-code functions too (Section 15).

## Section 7 — GDPR

**GDPR outcome:** Applies — personal data is collected through the tool's forms. The survey is no longer anonymous.

**Personal data collected:**
- Fields of expertise and the written expertise explanation (which may identify a person in a small group)
- Optional job title or role
- Optional basis for representation (may name a person or organisation)
- Overall comment and justifications (free text — may contain names or other personal information)
- The response is linked to the expert's **invitation**, which the consultant holds with the expert's name and email in Tool B (see Tool B spec). The response itself contains no name field.

**Business reason for holding invitation details (for the legal check):** audit traceability — being able to show that every response comes from a real, identifiable, invited person and not from fabricated input.

**Consent checkpoint on the form:** Yes — a checkbox and data statement must appear on the Welcome screen, before the expert starts. The checkbox must be ticked to continue. `consent_given_at` is recorded on the submission.

**Data statement text shown to users at the point of collection:**
> Your expertise details, your answers and, if you choose to give it, your job title are stored securely and used only to run and document this materiality assessment. Your answers are linked to your personal invitation, not to a name field, but the assessment owner can connect the invitation to you. They may be shared with the client company and its auditor. You can request deletion or anonymisation at any time by contacting: **anikalerch@greenfriend.org**.

**Deletion mechanism:** On request, the consultant clears the expert's name and email on the invitation in Tool B (shown as "Anonymised") and clears the optional title on the submission. Ratings, justifications, stakeholder group and expertise remain, so the assessment stays intact and traceable, but the response can no longer be connected to a person. Requests go to **anikalerch@greenfriend.org**, and the consultant (greenfriend) processes them.

> This is a legal requirement in the EU. The deletion contact (anikalerch@greenfriend.org) is confirmed. Whether the anonymisation approach and the legal basis for holding invitation details are acceptable must still be confirmed with legal advice **before real experts are invited** (it does not block the build). This spec is not legal advice.

## Section 8 — Screen and UI Structure

Every screen shows the **client company's logo prominently at the top** (or a dashed-border placeholder if none is uploaded) and a small, muted "Hosted on ✈ apus" credit at the very bottom. The Apus mark is never the prominent header.

### Welcome (with consent)

- **Purpose:** Introduce the survey, set expectations and obtain consent before any question is asked.
- **What is visible:** Client logo; title ("[Company name] sustainability survey", or "Sustainability survey" if no company name); the consultant-edited welcome text; three fixed bullets — "Your answers are linked to your personal invitation, not to a name field", "Time needed depends on the number of topics — you can save and continue later at any time", "Not sure about something? You can skip any criterion"; the **data statement** from Section 7; a **consent checkbox**; the note about the personal link ("This link is yours — it brings you back to your saved progress"); a "Get started →" button.
- **User actions:** Tick the consent checkbox; click "Get started →" (disabled until ticked). If the visitor already has a saved draft on this link, the button reads "Continue where you left off →".
- **What happens next:** New visitor → About you. Returning visitor with a draft → the first unfinished topic, with earlier answers and justifications restored.

### About you

- **Purpose:** Capture the expert's expertise and the perspective they answer from. The expert fills in everything themselves — nothing is pre-filled from the invitation.
- **What is visible:** "← Back"; "About you"; **Field(s) of expertise** — multi-select of E1 Climate change, E2 Pollution, E3 Water and marine resources, E4 Biodiversity and ecosystems, E5 Resource use and circular economy, S1 Own workforce, S2 Workers in the value chain, S3 Affected communities, S4 Consumers and end-users, G1 Business conduct, and Other / cross-cutting; **Explain your expertise** (short text, required); **Job title or role** (optional, with the hint "keep it general, for example 'Head of HR'"); **Which group best describes you?** — two labelled option grids, "Impact perspective" (default options: Employees, Suppliers, Local community, Customers, Workers in the value chain, NGOs / civil society, plus any **silent stakeholder** groups the consultant enabled, for example Nature and ecosystems, Species and biodiversity, Future generations) and "Financial perspective" (default options: Investors / shareholders, Lenders / creditors, Executive management, Supervisory board, Analysts / rating agencies). Options come from the assessment's stakeholder groups in Tool B. When a silent stakeholder group is chosen, an optional field appears: "On what basis do you represent it? (for example a study, method or mandate)". No name field is asked.
- **User actions:** Choose at least one expertise; write the explanation; optionally add a title; select exactly one group; click "Continue →" (disabled until expertise, explanation and one group are set).
- **What happens next:** Saves the draft, then moves to Rating Criteria.

### Rating Criteria

- **Purpose:** Explain what each criterion means before the expert uses it.
- **What is visible:** "← Back"; "How to rate each topic"; one or both blocks depending on the assessment's scope — "Impacts on the environment or society (positive or negative)" (Scale, Scope, Irremediability, Likelihood, each with a plain-language description) and/or "Financial risks and opportunities" (Magnitude, Likelihood); a short note that every rating needs a short justification and that any criterion can be skipped.
- **User actions:** Click "← Back" or "Continue →".
- **What happens next:** Moves to the first Topic rating page.

### Topic rating (repeats once per IRO in the assessment's scope)

- **Purpose:** Collect every applicable criterion and its justification for one IRO.
- **What is visible:** "← Previous topic" (hidden on the first topic); "Topic X of Y"; a progress bar; an IRO-type badge (Negative impact, Positive impact, Risk, Opportunity) and an Actual / Potential badge; the topic name and description; then every applicable criterion stacked vertically (see Section 9 for which criteria appear) — each with its large label, plain-language description, a row of six buttons (0–5), a live label showing what the hovered or selected value means, its own **Skip** control (with the tooltip "For anyone unsure or without direct expertise on this specific topic — it's fine to skip rather than guess") and, **when the assessment's justification mode is per criterion**, a **justification box** below the rating (compact, grows as the expert types; required once a value is chosen; hidden while skipped). When the mode is **per topic**, one justification box sits at the bottom of the topic instead. A skipped criterion shows "Skipped — that's okay, not everyone has a view on every topic" with an "Answer instead" link. A prominent **"Save and continue later"** button is visible on every topic page.
- **User actions:** Answer or skip each criterion; write the justification; go back; advance; save and continue later.
- **What happens next:** "Next topic →" (or "Continue →" on the last topic) saves the draft and is disabled while `assessments.mandatory = true` and any criterion on the page is neither answered nor skipped, or while a required justification is empty. Advancing past the last topic moves to Submit.

### Save and continue later (confirmation)

- **Purpose:** Let the expert leave on purpose and make sure they know how to come back.
- **What is visible:** "Your progress is saved."; the **personal link** with a "Copy link" button; the message "This link is the only way back to your answers — keep it. Anyone with this link can open your draft."; a note that unfinished answers are **not counted** in the results until the survey is submitted.
- **User actions:** Copy the link; close the page; or click "Back to the survey".
- **What happens next:** Opening the same link later resumes at the first unfinished topic. The same link is also shown right after consent as a reminder that progress saves as they go.

### Submit

- **Purpose:** A final confirmation step before the response is sent, plus a chance to add anything not covered by the structured questions.
- **What is visible:** "That's everything"; a note that "Previous" can still be used to review answers and that submitting is final; the optional **"Any other comments?"** textarea (labelled "anything you didn't get to say above, or context you think matters") directly above the Submit button; any missing required justification or unanswered criterion is listed if the assessment is mandatory.
- **User actions:** Type an optional comment; click "Submit survey →".
- **What happens next:** The response is written as one complete, all-or-nothing submission — every rating row and justification with the status set to submitted, or nothing at all — then moves to Thank you. If saving fails, the expert stays on this screen with their answers intact and can retry.

### Thank you

- **Purpose:** Close the loop for the expert.
- **What is visible:** "Thank you for your participation" and a short note that the answers will feed into the company's materiality assessment alongside everyone else's.
- **User actions:** None — end of flow.

### Already submitted / link not valid or closed

- **Purpose:** Handle links that cannot be used.
- **What is visible:** Already submitted — "You've already submitted this survey. Thank you." (read-only, no answers shown). Link not valid — "This link isn't valid. Please contact the person who invited you." Survey closed — shown when the assessment's cycle is no longer accepting responses (stage Signed off, or assessment end date passed).
- **User actions:** None.
- **What happens next:** End of flow.

## Section 9 — Logic and Calculations

**No calculation.** This tool captures a `value` (0–5) or empty (skipped) plus a justification per criterion and hands it to the database exactly as entered. All formulas — severity, override, impact and financial scores, materiality, discrepancy — live in Tool B (Section 9 of its spec).

**Display rules — which criteria a topic page shows** (this is which questions to ask, not a calculation):

| IRO | Criteria shown |
|-----|----------------|
| Negative impact, potential | Scale, Scope, Irremediability, Likelihood |
| Negative impact, actual | Scale, Scope, Irremediability (likelihood is not asked — an actual impact is already occurring) |
| Negative impact flagged **potential human rights impact** (owner-set flag on the IRO in Tool B) | Scale, Scope, Irremediability (likelihood is not asked — severity takes precedence) |
| Positive impact, potential | Scale, Scope, Likelihood |
| Positive impact, actual | Scale, Scope |
| Risk or opportunity | Magnitude, Likelihood |

**Gating rules:**
- Stakeholder group, at least one expertise and the expertise explanation are required before the first topic.
- A justification is required whenever a criterion has a value (per criterion mode), or once per topic when any criterion on it has a value (per topic mode). Skipped criteria need no justification.
- "Next topic" stays disabled while `assessments.mandatory = true` and any criterion on the page is neither answered nor skipped.
- Progress is saved on every "Next topic", every "Previous topic", and on "Save and continue later".
- One submission exists per invitation. After submission, no further changes are possible from the public side.
- Draft responses are never counted in any result.

**Edge cases:** If the same personal link is open in two tabs, the most recently saved answers win (last write wins). If the assessment is closed while a draft is open, the expert sees the "survey closed" message on their next save and cannot submit.
